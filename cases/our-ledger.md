# 우리 가계부 | 동기화·배포·복구 검증

## 프로젝트 요약
- **목적:** 한 가구의 두 사용자가 원화 수입·지출을 기록하는 자체 호스팅 가계부.
- **개발 방식:** 이지섭이 AI 도구와 협업해 개발한 프로젝트. IT 근무 경력과 별도로 소개합니다.
- **핵심 기술:** Kotlin, Spring Boot, PostgreSQL, Flyway, Android Jetpack Compose, Room, WorkManager, Docker, GitHub Actions, Coolify.
- **검토 기준일:** 2026-09-16. 원본은 운영 정보 보호를 위해 비공개입니다.

## 어떤 문제를 다루나
휴대폰에서 오프라인으로 기록한 변경을 서버와 다시 맞추는 과정에는 재전송, 동시 수정과 삭제 전파가 발생합니다. 서버 배포에서는 앱·서버 검증을 함께 고려하고, 백업 파일 생성뿐 아니라 데이터가 들어 있는 DB를 복원하는 경로가 필요합니다.

## 구조

주요 흐름은 다음과 같습니다.

```text
Android: Compose → Room / WorkManager
                       ↕ 동기화 API
Spring Boot / Spring Security → PostgreSQL / Flyway

GitHub Actions: 서버 검증 + Android 검증 → 조건부 배포 요청
백업 경로: 합성 데이터 준비 → 암호화 백업 → 복원 통합검증
```

## 확인 가능한 구현
| 문제 | 코드에 있는 처리 | 근거 파일 |
| --- | --- | --- |
| 변경 재전송·충돌 | 사용자와 mutation ID 기준 재전송 처리, 필드 버전 충돌 응답, 가계 소속 검사 | 서버 SyncController.kt |
| 한 번에 과도한 변경 처리 | pull 커서 단위 최대 200건, push 최대 100개 mutation | 서버 SyncController.kt |
| 컨테이너 자원·상태 관리 | 메모리·CPU·PID 제한, 로그 크기 제한, 준비 상태 검사, API 읽기 전용 파일시스템 | compose.coolify.yml |
| 검증되지 않은 배포 | 서버·Android 작업을 배포 선행 조건으로 연결 | .github/workflows/ci.yml |
| 비어 있는 DB만 복원하는 검증의 한계 | 합성 가계부·보안·감사·동기화 데이터를 준비한 백업/복원 통합검증 | ops/backup-integration-test.sh |

현재 구현의 정적 검토와 과거 CI 성공 기록은 서로 다른 근거입니다. 검토 당시 main 루트는 0d0cac7, 아래 CI의 대상 커밋은 3c753c9였습니다.
