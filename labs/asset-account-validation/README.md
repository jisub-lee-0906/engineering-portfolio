# 합성 IT 자산·계정 생명주기 검증 실습

## 성격

프로덕션 경험이 아닌 로컬 교육용 데모입니다. AI 에이전트가 작성하고 실행했으며, 사용자의 검증된 기술이나 고용 경력을 의미하지 않습니다.

## 목적과 구성

스크립트가 합성 CSV 자산 자료와 합성 JSON 신원·계정 자료를 임시로 만들고 읽기 전용 검증을 수행한 뒤 삭제합니다.

```text
[합성 assets.csv] ----+
                      +--> [로컬 규칙 검사] --> 이슈 목록/VALID --> 단언
[합성 identities.json]+                              |
                                                     +--> 임시 파일 삭제
```

검증 규칙:

1. 같은 `asset_id`가 두 번 나오면 `DUPLICATE_ASSET_ID`.
2. `employment_status=retired`인데 `account_status=active`이면 `RETIRED_ACTIVE_ACCOUNT`.
3. 두 규칙을 위반하지 않으면 `VALID`.

## 예상 대 실제

| 사례 | 예상 | 실제 |
|---|---|---|
| 중복 자산 ID | `DUPLICATE_ASSET_ID:A-100` | PASS |
| 퇴직자 활성 계정 불일치 | `RETIRED_ACTIVE_ACCOUNT:E-009` | PASS |
| 유효 자료 | 이슈 없음, `VALID` | PASS |

[실행 코드](run.cjs)와 [실행 로그](../evidence/execution.log)에서 정확한 출력과 종료 코드를 확인할 수 있습니다. 임시 자료는 각 실행의 `finally`에서 재귀 삭제합니다. 예상과 다르면 단언 실패로 종료 코드가 0이 아닙니다.

## 한계

- 모든 인물, ID, 자산은 합성이며 실제 조직 자료가 아닙니다.
- 실제 SaaS, 디렉터리, MDM, ITSM 또는 자산 관리 시스템에 접속하지 않습니다.
- 관리자 변경 작업 없이 로컬 파일을 읽어 규칙만 확인합니다.
- CSV 파서는 이 제한된 예제 형식만 처리하며 인용 부호, 쉼표 포함 필드 등 일반 CSV 전체 사양을 구현하지 않습니다.
- 효율 향상, 비용 절감 또는 운영 성과를 주장하지 않습니다.
